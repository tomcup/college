# git如何更改commit message

```bash
git commit --fixup:reword<commit>
git rebase -i --autosquash <commit>^
```
注意`rebase`的时候是对“上个commit”进行的，所以最后要加`^`，当然直接定位到上个commit也行。
其原理在于git自动创建一个以`amend!`为前缀的空commit，与`fixup:reword`不同的是，这会忽略目前的更改，也就是仅仅修改以前的commit message。比如：
```
amend! [原commit message开头部分]

[完整的原commit message]

# Please enter the commit message for your changes. Lines starting 
# with '#' will be ignored, and an empty message aborts the commit.
# 
# On branch main
# Your branch and 'origin/main' have diverged,
# and have 8 and 9 different commits each, respectively.
# 
```
`rebase`的时候会自动识别，将`rebase`指令自动从`pick`转换成`fixup -C`，比如：
```
pick 9228f4c # message1
pick 997fa0c # message2
pick d6ba1fd # message3
fixup -C 399fca3 # amend! message2 #empty
```
也就是说git已经自动识别到这个`amend`操作了，除非要干点别的操作，具体可以看些指令下面的注释（不写出了），否则直接退出，开始`rebase`。这个`amend!`的commit会被`fixup -C`自动删除，同时改变之前的commit。
这里似乎不需要`rebase --continue`，而是退出后直接开始，所以搞错了比较麻烦，
注意这里的`rebase`已经改写了commit历史，所以`push`的时候必须强制，当然推荐使用` --force-with-lease`，比较安全。
## 为何改个message这么麻烦？
git内部commit名是由以下内容的SHA-1哈希值计算得到的，一旦发生改变，后续一整串commit和要改变的commit一起都要改名，所以很麻烦。
- 代码快照（tree）
- 父 commit 的哈希
- 作者、提交者、时间戳
- 提交信息（message）
